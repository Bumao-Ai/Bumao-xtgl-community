XINSHOU-ZHINAN.txt · Bumao XTGL Community 新手指导（十分钟上手）
============================================================
给第一次拿到这份产品的人。照顺序做，不要跳步。
读完这份，你应该能：跑通自检、改一条条款、看懂闸门在拦什么。

一、这东西解决什么问题
------------------------------------------------------------
AI 助手「不听话」通常不是模型笨，是没人把「该怎么干」写清楚、也没人校验。
Bumao XTGL Community 把这件事故化成两层：
  · 条款（zhunze\\z*.json）——把要求写成一条条可判定的句子；
  · 闸门（BumaoXTGL_Community_v01.py）——用代码去查条款有没有被遵守，不靠自觉。
一句话：它不管 AI 说什么，只管 AI 做的东西合不合规矩。

二、三分钟跑通
------------------------------------------------------------
第 1 步  看版本：       type 00_meta\meta.json
          里面 version 是唯一版本真源，别处写的一律以它为准。

第 2 步  自报家门：     cd 10_rac
                        python BumaoXTGL_Community_v01.py whoami
          应看到版本、条款数、视图漂移 0 处、接入状态。

第 3 步  过闸：         python BumaoXTGL_Community_v01.py check --strict
          只有 ALL PASS 才允许改东西。FAIL 就先修 FAIL，不要「先干着」。

三、改了条款怎么生效（四步，缺一步等于没改）
------------------------------------------------------------
① 改真身    编辑 10_rac\zhunze\z*.json（只改这里）
② 渲染       python render.py write
③ 过闸      python BumaoXTGL_Community_v01.py check --strict
④ 记账      30_taizhang\biangeng_zhang.txt 追加一笔
为什么不能直接改 20_view 下的 .txt：那是由真身渲染出来的只读产物，
手改下一轮就被覆盖，而且闸门会报视图漂移（B1/B2）。

四、最容易犯的三个错
------------------------------------------------------------
① 拿「文件里有」当「界面上看得见」
   UI 改动必须真机截图；配置文件里写了不等于生效。
② 手改渲染产物
   20_view 只由 render.py 写。想改内容就改真身，想改视图就重新渲染。
③ 把「应该能跑」当「已验证」
   验收看实际输出，不看推断。跑不通就如实记「未验证」。

五、0.8 之后多出来的四条（都是「怎么算干完」）
------------------------------------------------------------
4.3  完成度五档：S0 立项 10% / S1 在研 35% / S2 可运行 65% / S3 已验收 90% / S4 已归档 100%。
     百分比只由档位换算，不许手填；允许降档且必须降。
4.4  两条健康分开判：宿主健康（A，机器本身）与规则系统健康（B，这套引擎）各给结束判据，
     两者都结束才叫「闭环」。禁止合成一个总分。
5.3  状态可人工覆盖：系统判定只是基线，人自己勾的写覆盖文件并留 by/at；
     但覆盖不得绕过闸门——勾成「完成」不会让自检变 PASS。
8.3  每日工作登记：一行一条六列（日期｜时间｜执行者｜任务｜干了什么｜详细指向），
     详细指向必须真实存在，滚动保留只迁不删。

七、想把它用到自己项目上
------------------------------------------------------------
1) 整个目录拷走即可，产品内没有任何绝对路径与个人信息（闸门 B6/B6b 会查）。
2) 先改 00_meta\meta.json 的 name / short / version，再改 zhunze 里的角色与路由条款。
3) 每加一条主条款，必须同时在 00_meta\jiancha_map.json 的 map 里登记 covers，
   否则闸门 B9「检查项登记覆盖全部条款」直接 FAIL —— 这是故意的，
   目的是不让「写了没查」的条款混进来。
4) 如果你的检查只能人工做，就在 map 里写 "check": "人工" 并给 evidence 指针；
   悬空条目（写了人工却没证据）按未登记处理。
