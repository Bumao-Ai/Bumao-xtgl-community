XINSHOU-ZHINAN.txt · Bumao XTGL Community 新手指导（十分钟上手）
============================================================
给第一次拿到这份产品的人。照顺序做，不要跳步。
读完这份，你应该能：跑通自检、改一条条款、看懂闸门在拦什么。

一、这东西解决什么问题
------------------------------------------------------------
AI 助手「不听话」通常不是模型笨，是没人把「该怎么干」写清楚、也没人校验。
Bumao XTGL Community 把这件事故化成两层：
  · 条款（zhunze\\z*.json）——把要求写成一条条可判定的句子；
  · 闸门（BumaoXTGL_Community_v01.py）——用代码去查条款有没有被遵守，不靠自觉。
一句话：它不管 AI 说什么，只管 AI 做的东西合不合规矩。

二、三分钟跑通
------------------------------------------------------------
第 1 步  看版本：       type 00_meta\meta.json
          里面 version 是唯一版本真源，别处写的一律以它为准。

第 2 步  自报家门：     cd 10_rac
                        python BumaoXTGL_Community_v01.py whoami
          应看到版本、条款数、视图漂移 0 处、接入状态。

第 3 步  过闸：         python BumaoXTGL_Community_v01.py check --strict
          只有 ALL PASS 才允许改东西。FAIL 就先修 FAIL，不要「先干着」。

三、改了条款怎么生效（四步，缺一步等于没改）
------------------------------------------------------------
① 改真身    编辑 10_rac\zhunze\z*.json（只改这里）
② 渲染       python render.py write
③ 过闸      python BumaoXTGL_Community_v01.py check --strict
④ 记账      30_taizhang\biangeng_zhang.txt 追加一笔
为什么不能直接改 20_view 下的 .txt：那是由真身渲染出来的只读产物，
手改下一轮就被覆盖，而且闸门会报视图漂移（B1/B2）。

四、最容易犯的三个错
------------------------------------------------------------
① 拿「文件里有」当「界面上看得见」
   UI 改动必须真机截图；配置文件里写了不等于生效。
② 手改渲染产物
   20_view 只由 render.py 写。想改内容就改真身，想改视图就重新渲染。
③ 把「应该能跑」当「已验证」
   验收看实际输出，不看推断。跑不通就如实记「未验证」。

五、0.8 之后多出来的四条（都是「怎么算干完」）
------------------------------------------------------------
4.3  完成度五档：S0 立项 10% / S1 在研 35% / S2 可运行 65% / S3 已验收 90% / S4 已归档 100%。
     百分比只由档位换算，不许手填；允许降档且必须降。
4.4  两条健康分开判：宿主健康（A，机器本身）与规则系统健康（B，这套引擎）各给结束判据，
     两者都结束才叫「闭环」。禁止合成一个总分。
5.3  状态可人工覆盖：系统判定只是基线，人自己勾的写覆盖文件并留 by/at；
     但覆盖不得绕过闸门——勾成「完成」不会让自检变 PASS。
8.3  每日工作登记：一行一条六列（日期｜时间｜执行者｜任务｜干了什么｜详细指向），
     详细指向必须真实存在，滚动保留只迁不删。

六、目录一句话
------------------------------------------------------------
00_meta       元信息、版本单点、检查项登记表
10_rac        执行器 ＋ 唯一真身 zhunze\\（只改这里）
20_view       render.py 独占写入的视图，当前版本全文归档也在这里
30_taizhang   变更台账 ＋ 差错台账 ＋ 项目记录（只追加）
40_renwu      任务执行区
90_lishi      历史归档，只读

七、想把它用到自己项目上
------------------------------------------------------------
1) 整个目录拷走即可，产品内没有任何绝对路径与个人信息（闸门 B6/B6b 会查）。
2) 先改 00_meta\meta.json 的 name / short / version，再改 zhunze 里的角色与路由条款。
3) 每加一条主条款，必须同时在 00_meta\jiancha_map.json 的 map 里登记 covers，
   否则闸门 B9「检查项登记覆盖全部条款」直接 FAIL —— 这是故意的，
   目的是不让「写了没查」的条款混进来。
4) 如果你的检查只能人工做，就在 map 里写 "check": "人工" 并给 evidence 指针；
   悬空条目（写了人工却没证据）按未登记处理。

------------------------------------------------------------

## English

XINSHOU-ZHINAN.txt · Bumao XTGL Community Beginner's Guide (Get Started in Ten Minutes)
============================================================
For the person who receives this product for the first time. Do it in order; do not skip steps.
After reading this, you should be able to: run the self-check, change one clause, and understand what the gate is blocking.

1. What problem this thing solves
------------------------------------------------------------
An AI assistant "not obeying" is usually not because the model is stupid, but because nobody wrote down "how it should work" clearly and nobody checks it.
Bumao XTGL Community turns this into two layers:
  · Clauses (zhunze\z*.json) — write the requirements as sentences that can each be judged;
  · Gate (BumaoXTGL_Community_v01.py) — use code to check whether the clauses are obeyed, not relying on self-discipline.
In one sentence: it does not care what the AI says; it only cares whether what the AI produces conforms to the rules.

2. Get it running in three minutes
------------------------------------------------------------
Step 1  Check the version:   type 00_meta\meta.json
        In it, version is the single source of the version; wherever else it is written, that one prevails.

Step 2  Introduce itself:    cd 10_rac
                            python BumaoXTGL_Community_v01.py whoami
        You should see the version, the clause count, 0 view drifts, and the connection status.

Step 3  Pass the gate:       python BumaoXTGL_Community_v01.py check --strict
        Only with ALL PASS are you allowed to change things. If it FAILs, fix the FAIL first; do not "start working anyway".

3. How a clause change takes effect (four steps; missing one equals no change)
------------------------------------------------------------
① Change the canonical source    edit 10_rac\zhunze\z*.json (change only here)
② Render                        python render.py write
③ Pass the gate                 python BumaoXTGL_Community_v01.py check --strict
④ Record it                      append one entry to 30_taizhang\biangeng_zhang.txt
Why you cannot directly edit the .txt files under 20_view: they are read-only artifacts rendered from the canonical source,
a manual edit is overwritten in the next round, and the gate reports view drift (B1/B2).

4. The three most common mistakes
------------------------------------------------------------
① Treating "it is in the file" as "it is visible in the interface"
   UI changes require a screenshot on the real machine; writing it in a configuration file does not mean it takes effect.
② Manually editing rendered artifacts
   20_view is written only by render.py. To change content, change the canonical source; to change the view, re-render.
③ Treating "it should run" as "it has been verified"
   Acceptance looks at the actual output, not inference. If it does not run, honestly record "unverified".

5. The four extra items added after 0.8 (all about "how work is considered done")
------------------------------------------------------------
4.3  Five levels of completeness: S0 initiated 10% / S1 in progress 35% / S2 runnable 65% / S3 accepted 90% / S4 archived 100%.
     The percentage is converted only from the level and must not be filled in by hand; downgrading is allowed and mandatory.
4.4  Two healths judged separately: host health (A, the machine itself) and rule-system health (B, this engine) each get their own completion criterion;
     only when both are complete is it called a "closed loop". Combining them into one total score is forbidden.
5.3  Status can be manually overridden: the system verdict is only a baseline; what a person ticks themselves is written to an override file with by/at;
     but an override must not bypass the gate — ticking "done" does not make the self-check PASS.
8.3  Daily work log: one line per entry with six columns (date | time | executor | task | what was done | detailed pointer);
     the detailed pointer must really exist; rolling retention only migrates, never deletes.

6. The directories in one sentence
------------------------------------------------------------
00_meta       meta information, single version point, check-item registry
10_rac        executor + the single canonical source zhunze\ (change only here)
20_view       the view written exclusively by render.py; the full text of the current version is archived here too
30_taizhang   change ledger + defect ledger + project records (append only)
40_renwu      task execution area
90_lishi      historical archive, read-only

7. Want to use it on your own project
------------------------------------------------------------
1) Just copy the whole directory; the product contains no absolute paths and no personal information (gates B6/B6b check this).
2) First change name / short / version in 00_meta\meta.json, then change the role and routing clauses in zhunze.
3) For every main clause you add, you must also register covers in the map of 00_meta\jiancha_map.json,
   otherwise gate B9 "check-item registration covers all clauses" fails directly — this is intentional,
   the purpose is to prevent clauses that are "written but not checked" from slipping in.
4) If your check can only be done manually, write "check": "人工" in the map and give an evidence pointer;
   dangling entries (manual declared but no evidence) are treated as unregistered.

8. License and feedback
------------------------------------------------------------
Apache-2.0 (see 10_rac\LICENSE). If you want to contribute back after changes, write clearly the nature and the evidence pointer in the change ledger.
