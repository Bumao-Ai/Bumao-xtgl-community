# Bumao XTGL 控制台 · 新手教程（详细版）

> 这份教程假设你**从没装过**这套东西。按顺序做，每一步都有验收方式。
> 全程不需要联网，不需要 `pip install`，不需要 Node.js。

---

## 0. 先搞清楚它是什么

控制台是一个**本地网页**：你的电脑上跑一个小服务（Python），浏览器打开
`http://127.0.0.1:端口/` 就能看站点状态。

它不是云服务，不联网也能用；它也不修改你的项目（除了首次向导写配置、建任务）。

---

## 1. 准备工作（5 分钟）

### 1.1 确认 Python

打开 PowerShell（Win + X → 终端），输入：

```powershell
python --version
```

看到 `Python 3.8.x` 或更高即可。若提示「不是内部或外部命令」：

1. 去 python.org 下载 3.8+ 安装包；
2. 安装时**勾选 Add Python to PATH**；
3. 重开终端，再试一次。

### 1.2 找到控制台目录

两个开源仓库各有一份，路径类似：

```text
<仓库>\20_view\web\
  ├─ serve.py          启动入口
  ├─ index.html        主界面
  ├─ setup.html        首次向导
  ├─ xtgl_core.py      内核
  ├─ web_config.json   配置（唯一允许两端不同）
  └─ README.md         运行说明
```

## 2. 第一次启动（3 分钟）

在控制台目录打开终端：

```powershell
cd <仓库>\20_view\web
python serve.py
```

你会看到：

```text
========================================================
 Bumao XTGL · 控制台
 页面 http://127.0.0.1:8802/
 项目根 <项目根>/community
 内核 0.10 · Python 3.12.14
 浏览器 Chrome
 Ctrl+C 退出
========================================================
```

**验收**：浏览器自动打开（优先 Chrome）；没弹出就手动打开上面打印的地址。

> Windows 也可以双击 `qidong_kongzhitai.bat`，效果一样。
> 端口被占用会自动向后找，最多试 40 个；一切以终端打印的地址为准。

## 3. 首次向导：把控制台指向一个项目

如果目录里没有项目，页面会显示「首次运行」，点 **打开首次向导**，或直接访问
`http://127.0.0.1:8802/setup`。

### 第 1 步：选择项目目录

- 已有项目：填它的根目录（里面应有 `00_meta/meta.json`）；
- 没有项目：填一个**空目录**，勾选「新建工作区」，点「生成骨架」。

生成骨架会创建：

```text
00_meta/meta.json      元信息（版本单点）
rules/r01_default.json 两条示例规则
10_rac/                引擎目录（可选）
30_taizhang/           台账
40_renwu/              任务
```

只补缺，不覆盖已有文件。

### 第 2 步：检测环境

点「检测」，逐项看：

| 检查项 | 通过标准 |
|---|---|
| Python | 3.8+ |
| 项目目录 | 存在且可读 |
| 00_meta/meta.json | 能解析 |
| 引擎 | 能定位到命令（没有引擎只是警告） |
| 规则层 | 默认层目录存在 |
| 项目可写 | 建任务需要 |

红色项必须修；黄色警告可以继续。

### 第 3 步：设置规则层

三个目录，按优先级合并：

```text
core（内核，不可被用户覆盖） > default（默认） > user（用户）
```

- 默认层必填（例如 `rules` 或 `zhunze`）；
- 内核层、用户层可以留空；
- 用户层与内核层同编号时，该条会被**拒绝**并在页面顶部报告。

### 第 4 步：创建第一个任务（可选）

填任务名（例如「搭好第一版工作区」），点「创建任务」。
会在 `40_renwu/<任务名>/` 下生成 `benci_gongcheng.txt` 骨架。

最后点 **保存配置并进入控制台**。

**验收**：页面顶部显示项目根，四张卡都有数据，没有红色报错。

## 4. 主界面怎么读

| 卡片 | 看什么 |
|---|---|
| 项目元信息 | 版本、名称、性质等，来自 `00_meta/meta.json` |
| 闸门自检 | 点「运行闸门检查」真实跑引擎，绿=ALL PASS |
| 规则条款清单 | core/default/user 三层合并结果；点一行看条款 |
| 模块 | 同一内核下的模块清单与版本兼容 |
| 长期目标 | A 类资产里的目标、进度、关联项目；可导出 |
| 任务留档 | 每个任务是否有留档 |

首屏走 `?fast=1`，不跑闸门（毫秒级）；闸门必须手动点，避免页面卡 10–40 秒。

## 5. 规则怎么写

一个规则文件长这样：

```json
{
  "ch": 1,
  "file": "r01_default.json",
  "chapter_title": "1. 默认规则",
  "clauses": [
    {"id": "1.1", "root": "1.1", "title": "1.1 改动前先备份",
     "body": ["覆盖写之前，同目录留一份带时间戳的 .bak。"]}
  ]
}
```

规则放哪：

- 默认层：`web_config.json` 里 `rules.default.dir` 指向的目录；
- 内核层：`rules.core.dir`（用户不可覆盖）；
- 用户层：`rules.user.dir`（可覆盖默认层）。

改完规则刷新页面即可看到，不需要重启服务。

## 6. 任务、日志与留档

### 6.1 任务：短期 / 长期

任务页只有两张板，字段完全一样：

```text
[编号] 目标 / 阶段 / 状态 / 进度 / 关联项目 / 关联文件 / 下一步 / 证据 / 复核
```

短期任务放本周/本月要收口的事，长期任务放阶段目标。两者都从仓库外的
`~/.xtgl/` 读取，格式相同，改完刷新即可。

### 6.2 留档：每个项目必须有

每个项目目录至少一份留档，三种文件名都认：

```text
benci_gongcheng.txt / renwu_liudang.txt / xiangmu_jilu.txt（或文件名含 liudang）
```

留档固定三段：摘要头（日期/执行者/任务/状态/目标）、正文明细、索引尾。
执行者写「模型名 + 客户端名」，不要署用户本人的名字。

### 6.3 日志：天 → 项目 → 时间线

工作日志是追溯的根，不是流水账：

- 第一层：按天；
- 第二层：同一天里按项目合并（去掉括号说明后相同的归为一组）；
- 第三层：组内按时间排列每次登记，每条指向当天的项目留档。

**每次更新都必须登记**：

```powershell
（当前命令面无 log 子命令）在 30_taizhang\xiangmu_jilu.txt 手工追加一条本次记录，写后回读确认
```

日志的「详细指向」必须真实存在；主系统 B41 / B42 / B43 会逐条检查，
不满足即 FAIL，不允许记账。

## 7. 长期目标与导出

目标只有一份，放在 A 类资产里：

```text
你的 goals 文件（web_config 的 goals 或环境变量 XTGL_GOALS）
```

控制台「长期目标」卡会读它：目标、阶段、状态、进度、关联项目、关联文件缺失数。
右上角「导出 Markdown」会生成一份包含源文件路径、关联项目、关联文件存在状态的清单
（只导索引，不复制项目文件）。

文件路径由 `web_config.json` 的 `goals` 字段指定；留空就不显示。

## 9. 常见问题

**Q1：双击 .bat 一闪就退？**
A：三种常见原因——Python 不在 PATH、端口被占、默认浏览器起不来。
先在终端跑 `python serve.py` 看真实报错。

**Q2：页面显示「读取失败」？**
A：多半是直接双击了 `index.html`。必须经 `serve.py` 启动，页面才能调 `/api/*`。

**Q3：浏览器不是 Chrome / 打不开？**
A：服务端会优先用 Chrome 新窗口打开；找不到 Chrome 才用系统默认浏览器。
也可以手动把终端打印的地址粘到任意浏览器。

**Q4：闸门一直转圈？**
A：闸门是真实执行，项目大时要十几秒。首屏不跑闸门，点按钮才跑。

**Q5：端口冲突？**
A：会自动向后找 40 个；以终端打印的地址为准。

**Q6：能放到别的电脑吗？**
A：能。整个仓库拷走即可；`project_root` 留空时按「web 的上级项目根」解析，整体搬家不破。

## 10. 安全边界

- 只监听 `127.0.0.1`，不做鉴权，不要暴露到局域网/公网；
- 写接口只接受本机页面调用（要求 `X-XTGL-Setup: 1`）；
- 除首次向导的四个写接口外，控制台不修改项目文件；
- 文档接口只读白名单文件。

---

## 11. 卸载 / 停止

- 停止服务：终端里 `Ctrl+C`；
- 删除：直接删仓库目录即可，没有注册表、没有系统服务、没有残留进程。

## 11.5 功能打开方式、规则配置、规则包与功能包

### 功能怎么打开

控制台的能力分两处声明，两处对上了才算「打开」：

- `web_config.json` 的 `capabilities`：本端允许启用的能力名（新能力默认关，先写进 `capabilities_off` 才不会被误开）；
- `modules.json` 的 `status`：模块取 `active`／`planned`／`disabled`，没有声明的能力不会出现在页面上。

做法：在 `web_config.json` 的 `capabilities` 里补上能力名，确认 `modules.json` 有同 `id` 的模块，重启服务即可；关掉就把名字移回 `capabilities_off`。

### 规则配置方法

规则真身按层放：`core`（内核，只读）→ `default`（默认）→ `user`（用户）。用户层与内核层同编号时该条会被拒绝并在页面顶部报告；改规则只改 `user` 层，不动 `core`。社区版规则真身在 `10_rac/zhunze/z00–z10.json`，改完刷新页面，闸门会重新判定并给出结论。

### 规则包与功能包

- **规则包**：条款本身（JSON 文件，可挂载、可替换、可导出），不含代码；
- **功能包**：模块与接口（`modules.json` 声明 ＋ 页面／服务实现），不写条款。

两者分开：换规则包不动代码，换功能包不动条款。

控制台右上角有「📖 新手教程」按钮，点它随时回到本页；本页左上角「← 回控制台」回到主界面。

## 从规则库挂一条规则（六步）

规则库在宿主层 `00_meta/rules_library/`（端根目录受 B5b 命名约束，库不放根上），与生效规则目录分开；
五类预置包（备份与保留／留痕与台账／凭据与闸门／回滚与证据／日志与复审）规则数组一律为空、默认不启用。
挂载步骤：

1. 复制 `00_meta/rules_library/examples/example-template.json`，改名放进 `00_meta/rules_library/packs/`；
2. 按 `00_meta/rules_library/schema.json` 填自己的规则——只写自己的动作与范围，不写任何条款正文；
   天数、份数、条数、阈值一律留空由自己填；
3. 把该包的 `enabled` 改成 `true`（不改就永远不生效）；
4. 跑 `python 20_view/web/module_check.py`：包格式错必须 FAIL；
5. 跑闸门 `check --strict`：必须全绿；
6. 看前端「能力挂载」里的规则库行——未启用的包不进快照、不显示。
